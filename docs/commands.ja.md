# コマンドリファレンス

4本のコマンドの全フラグを、既定値とその既定値である理由つきで並べます。実際の
`argparse` の定義から起こしたものです。このファイルと `--help` が食い違ったら、
正しいのは `--help` で、こちらが古くなっています。

4本すべてに共通するのは `--config`、`--show-config`、`--lang` です。値がどう決まるかは
[configuration.ja.md](configuration.ja.md) を見てください。

- [gguf-fetch](#gguf-fetch)
- [gguf-probe](#gguf-probe)
- [gguf-plan](#gguf-plan)

## gguf-fetch

Hugging Face から GGUF を落とします。ただし、どれが載るかを決めてからです。

```
gguf-fetch <repo> [mode] [options]
```

`<repo>` は Hugging Face のリポジトリ id (`ornith-ai/Ornith-1.5-35B-A3B-GGUF`) です。
モードのフラグを付けなければ、判定表を出すだけで何も落としません。

### モード（排他）

| フラグ | 既定 | 何をするか |
| :-- | :-- | :-- |
| *(なし)* | — | 判定だけ。何も落としません。 |
| `--fit` | off | 予算に載るもののうち大きいほうから落とします。 |
| `--pick NAME` | — | 指定した1本だけ落とします。まず量子化ラベルで、次にファイル名の部分一致で探します。候補に入っていないファイルにも届きます (`--pick mtp`)。 |
| `--all` | off | リポジトリのルート直下の GGUF を全部落とします。 |

### `--fit` が何を取るか

| フラグ | 既定 | 補足 |
| :-- | --: | :-- |
| `--top N` | `3` | 何本取るか。1本にしないのは、予算の境界付近では見積りはあくまで見積りで、1段下をディスクに置いておく価値があるからです。 |
| `--min-ctx N` | `16384` | この ctx に届いたものだけを「載る」と数えます。起動はするが ctx 4k で止まる、は答えになっていません。 |
| `--min-bpw F` | *未設定* | 実測の bits-per-weight がこれ未満のものを落とします。名前ではなく中身で切ります。 |
| `--spread` | off | 上から N 本ではなく、bpw の幅を取って N 本。付けないと、24量子化のリポジトリから同じビット帯の3本が返ります。 |
| `--only GLOB` | *未設定* | glob に一致する候補だけを残します（ラベルかファイル名、大文字小文字は区別しません）。繰り返し指定できます。**名前での絞り込みであって、品質の判断ではありません。** |
| `--exclude GLOB` | *未設定* | glob に一致する候補を落とします。繰り返し指定できます。 |

### 付属ファイル

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--mmproj {auto,all,none}` | `auto` | ビジョン投影。`auto` は最小の1本を取ります。これが無いとマルチモーダルモデルは何も見えません。 |
| `--extras {none,mtp,all}` | `none` | サブディレクトリ (`MTP/`、`imatrix/`) の GGUF。本体ではないので、載るかどうかの判定には出しません。`mtp` は draft/MTP のファイルだけを取ります。既定が `none` なのは、そのファイルが何に使うものかをこのツールが読み取れないからです。 |

### 決めるまでに何を読むか

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--probe {one,all,none}` | `one` | `one` は代表1本のヘッダ（約 12 MiB）を読み、その KV の単価を全行に当てます。量子化が変えるのはテンソルの*型*であって*名前*ではないので、これで通ります。`all` は候補を全部読みます。`none` は何も読まず、ファイルサイズだけで判定し、そうと分かるように書きます。 |

### 予算

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--vram F` | 自動検出 | GiB。このマシンから取ります。別のマシン向けに計画を立てるなら渡してください。 |
| `--overhead F` | `1.0` | GiB。計算バッファ、CUDA コンテキスト、投機的デコードの分です。 |
| `--kv {f16,q8_0,auto}` | `auto` | `auto` は f16 で `--min-ctx` に届かないとき `q8_0` に切り替えます。 |
| `--llama-server PATH` | `llama-server` | 繰り返し指定でき、カンマ区切りも受け付けます。`gguf-plan` と同じ関数で解決するので、両方のコマンドが同じデバイスを見ます。 |

### 出力と実行

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--dir PATH` | `.`（または `models_dir`） | この下にリポジトリ名のサブディレクトリを作ります。 |
| `--revision REF` | `main` | ブランチ、タグ、コミット。 |
| `--dry-run` | off | 実行する `hf download` を出して止まります。ディスクが足りないときも出します。 |
| `-y`, `--yes` | off | 確認を飛ばします。 |
| `--json` | off | 候補・判定・bpw・選んだものを JSON で。 |
| `--hf-bin PATH` | `hf`、次に `huggingface-cli` | どの実行ファイルでダウンロードするか。 |
| `--refresh` | off | 設定ファイルの `vram`/`threads`/`device` を無視して取り直します。 |

### やらないこと

- ディスクの空きがダウンロードより小さいときに書き込むこと（`--dry-run` はコマンドを出しますが、終了コードは 1 のままです）。
- サーバが HTTP の `Range` を無視したときに続けること。21 GB を黙って受け取らないための最後の砦です。
- ルート直下のファイルを、bits-per-weight が 0.5–33 の外にあるのに量子化として扱うこと。`imatrix_unsloth.gguf` は 27B のパラメータ数に対して 0.004 bpw です。
- `n_tensors >= block_count` を満たさないファイルから KV の単価を借りること。

書き込み先が git の作業ツリーの中にあるときは、警告は出しますが続けます。

## gguf-probe

ローカルの GGUF を読んで、何が書いてあるかを出します。

```
gguf-probe [paths...] [options]
```

パスには glob 文字 (`*?[`) を含められます。展開するのはツール自身なので、クォートしても
問題ありません。

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--json` | off | 機械可読。JSON には各ファイルの**絶対パス**が入るので、`gguf-plan` が `-m` に実物を書けます。 |
| `--roles` | off | 層によって型が変わるテンソル役割を全部。 |
| `--out PATH` | *未設定* | このファイルにも保存します。結果は画面にも出ます。 |

言語モデルを2本以上読むと、比較表が付きます。

## gguf-plan

`gguf-probe --json` の結果と VRAM 予算から、起動コマンドを出します。

```
gguf-plan <gguf.json> [options]
```

`--pick` を付けなければ、全量子化の判定表を出します。`--pick` を付ければ、その1本の
起動コマンドと config を出します。

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--pick NAME` | *未設定* | ファイル名の一部。 |
| `--ctx N` | 切り下げ | 省くと、載る最大ではなく、載るきりのいい ctx を選びます。69,632 は余りが 0.02 GiB しか残らず、context の増分は 6% です。 |
| `--kv {f16,q8_0,auto}` | `auto` | `auto` は f16 で入らないとき、理由を添えて `q8_0` に切り替えます。 |
| `--target {llama-server,ollama,lmstudio}` | `llama-server` | 全部を書けるのは `llama-server` だけです。残り2つは近似で、そうと分かるように書きます。 |
| `--vram F` | 自動検出 | GiB。 |
| `--overhead F` | `1.0` | GiB。 |
| `--model-path PATH` | JSON から | `-m` の後ろに書く値。 |
| `--port N` | `8085` | |
| `--device ID` | 自動検出 | `CUDA0` / `ROCm0` / `Vulkan0`。NVIDIA が見つからなければ推測せず、まるごと省きます。 |
| `--threads N` | 物理コア | **論理ではなく物理**です。SMT の相方まで llama.cpp に渡すと、行列積がむしろ遅くなることがあります。 |
| `--llama-server PATH` | `llama-server` | 繰り返し指定できます。CUDA ビルドからは ROCm デバイスが見えないので、使うビルドは全部書いてください。 |
| `--write-config [PATH]` | `gguf-fit.toml` | いまの値を設定ファイルに固定します。`--force` なしでは上書きしません。 |
| `--force` | off | `--write-config` の上書きを許します。 |
| `--refresh` | off | 設定ファイルの値を使わず、`vram`/`threads`/`device` を取り直します。 |

## gguf-calibrate

このマシンを1回測って、予算計算を推測でなくします。

```
gguf-calibrate --model /models/your.gguf [options]
```

ctx ごとに `llama-server` を起動し、`/health` を待ち、リクエストを1回通し、`nvidia-smi` で
増分を読み、直線を引きます。`nvidia-smi` が要ります。ベンチマークは回しません。

| フラグ | 既定 | 補足 |
| :-- | :-- | :-- |
| `--model PATH` | *必須* | 測るのに使う GGUF。 |
| `--ctx LIST` | `32768,65536` | **2つ以上必要です。** 1点では傾きと切片を分離できません。「KV 比が 0.61」と「比は 0.531 のままオーバーヘッドが増えた」は、同じ1つの数字になります。 |
| `--kv LIST` | `f16,q8_0` | どの KV 型で直線を引くか。 |
| `--extra "ARGS"` | *未設定* | `llama-server` に足すフラグ。**本番と同じものを渡してください。**数字はこれで動きます。 |
| `--warmup-tokens N` | `2048` | ウォームアップ1回のプロンプト長。既定の `--batch-size` に合わせてあります。増やしても意味はありません。8 → 2048 トークンで結果は 10 MiB しか動きませんでした。 |
| `--no-warmup` | off | リクエストを省きます。その分、結果が 110 MiB ほど低く出ます。 |
| `--port N` | `18085` | わざと 8085 にしていません。すでに動いているサーバとぶつからないためです。 |
| `--device ID` | 自動検出 | |
| `--threads N` | 物理コア | |
| `--llama-server PATH` | `llama-server` | |
| `--write-config [PATH]` | `gguf-fit.toml` | 較正ブロックを書きます。差し替えるのはそのブロックだけで、コメントはそのまま残します。書く前に TOML として読み直すので、失敗して壊れたファイルが残ることはありません。**どのモデルで**測った数字かも書き残します。 |

同じ条件で2回通して4点とも 1 MiB の差もなく一致したので、1回測れば足ります。あとで値が
動いたら、それは環境のほうが変わったということです。
